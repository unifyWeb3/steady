# 55 — Business / Ecosystem Case (strongest honest thesis)

**Why DreamDEX wants friction:** churn, not caution, kills venues. Blown-up retail quits; calibrated retail persists, redeems (recovering forgotten volume), and tightens books via IOC crosses that pay makers. Steady trades impulsive volume for *lifetime* volume.

- Trading activity: every tap is a real IOC cross (maker-earning flow); Ride-style parlays could later compound it — deliberately not built.
- Retained/better users: max-loss framing lowers first-trade fear; cooldown prevents blowup-quit; Brier turns luck into skill feedback.
- Ecosystem trust: explorer-linked receipts + oracle audit links + SDK feedback report = verifiability standard other submissions can reuse.
- Discoverability: homepage explains the venue (windows, payout, void 0.5) in plain language — onboarding DreamDEX lacks.
- Post-hackathon: (1) trader operating layer (keep), (2) policy API for third-party/agent routers — agents propose, Steady policy disposes (extension, not built), (3) calibration leaderboard *of Brier, not PnL* (extension). Non-core: social, tokens, rooms.
